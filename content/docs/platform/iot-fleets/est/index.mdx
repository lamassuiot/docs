Enrollment over Secure Transport (EST) is a protocol for obtaining and renewing X.509 certificates over HTTPS. An EST client communicates with an EST server, which handles certificate requests and provides certification authority certificates. The standard defines messages, operations and authentication mechanisms. [RFC 7030](https://www.rfc-editor.org/rfc/rfc7030.html)

## Operations

Operation paths are appended to the `/.well-known/est` prefix, which may include a label identifying the CA or service.

| Operation | Method | Purpose | Server support |
|---|---|---|---|
| `/cacerts` | GET | Retrieve CA certificates. | Mandatory |
| `/simpleenroll` | POST | Request an initial certificate using a CSR. | Mandatory |
| `/simplereenroll` | POST | Request certificate renewal or rekeying. | Mandatory |
| `/serverkeygen` | POST | Request a server-generated key and its certificate. | Optional |
| `/csrattrs` | GET | Retrieve suggested CSR attributes. | Optional |
| `/fullcmc` | POST | Submit a Full CMC request. | Optional |

## Authentication and messages

EST uses TLS to protect the exchange. The client authenticates the server, and the server authenticates and authorizes the client using the mechanisms defined by the standard. Initial CA certificate distribution has specific conditions for establishing trust. [RFC 7030, sections 3.3 and 4.1](https://www.rfc-editor.org/rfc/rfc7030.html)

The `/simpleenroll` and `/simplereenroll` requests use a PKCS#10 CSR. The certificate response uses PKCS#7. The `/serverkeygen` response is `multipart/mixed` and contains the key and certificate. The standard also defines Full CMC requests and responses and the CSR attributes format. [RFC 7030, section 3.2.4](https://www.rfc-editor.org/rfc/rfc7030.html#section-3.2.4)

See [EST in Lamassu](/docs/platform/iot-fleets/est/configuration) for the available operations and their configuration.
