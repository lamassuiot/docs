Error codes and diagnostics

The EST controller normally returns 400 when rejecting input and 500 when the service rejects or fails the operation. A 500 can also represent a policy denial; it does not mean retrying is safe. Gateway can produce its own codes and bodies. Examine the actual body and persisted result.

Symptom or messageWhat to check
curl rejects TLS, name or issuerURL, clock, server SAN and approved root in est-trust.pem. Resolve trust in Deployment; do not skip verification.
404 or missing APSPublic route /.well-known/est/{DMS_ID}/{operation} and existing DMS. APS is not the service name.
400, CSR or format errorContent-Type: application/pkcs10, Base64 of DER, valid signature and a body preserved without double encoding.
Missing credential or invalid certificateOperation mode, validating CA, dates, revocation and credential delivery by Gateway. Do not confuse server TLS trust with the bootstrap CA.
Webhook denies, times out or responds without authorizationConfiguration, connectivity and JSON response with authorized: true. There is no automatic fallback to NO_AUTH.
device not preregisteredPRE_REGISTRATION requires an existing inventory entry.
forbiddenNewEnrollmentAn existing device requires replacement to be enabled, even in No Identity. Investigate before enabling the flag.
Different owning DMSCN/ID, global inventory and owning DMS; do not reuse an ID from another context.
invalid RawSubject bytesCSR subject versus the current certificate. Preserve its attributes as well as its CN.
invalid reenroll windowCurrent identity's NotAfter and reenrollment_delta. Alert thresholds do not change that window.
Current certificate revokedRenewal rejected; prepare authorized recovery according to the cause.
CA, profile or signing errorActive CA, available key, selected profile and restrictions. Successful cacerts does not prove issuance.
HTTP 200 without a device connectionInstalled pair, chain, uses, consumer trust and permissions. Also check the slot and history.
Timeout or error after issuanceNew certificates, current slot and previous identity's state before retrying.

Compatibility notes

The examples use the contract of the examined backend. Do not automatically attribute that behavior to another release. Check the saved renewal mode after migration and Gateway behavior with expired certificates and the bootstrap CA.

The default response is Base64-encoded DER PKCS#7; PEM through Accept: application/x-pem-file is a Lamassu extension. ServerKeyGen returns multipart and requires handling each part separately. See the EST reference.

EST enrollment fails

  1. Check HTTPS with the approved root and query cacerts for the correct APS.
  2. Review the saved DMS: protocol, registration, authentication for that operation, CA, profile and window.
  3. Verify the CSR locally and relate its CN to the inventory.
  4. Make one request, save headers/body and query the device and certificates.
  5. If you receive an identity, check the key, subject, use and connection with the consumer.

External bootstrap revocation checks have limitations: absence of evidence can be accepted, and OCSP Unknown does not cause the same rejection as Revoked. Do not assume a policy that rejects every uncertainty. An intermediate CA in the TLS chain does not prove that the entire chain reached the DMS validator either.

For logs, networking, pods or Gateway headers, continue in Deployment troubleshooting. For identities issued, revoked or bound partially, use Renewal and recovery and Devices and identities.
