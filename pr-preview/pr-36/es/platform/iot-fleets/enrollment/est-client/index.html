Integra el cliente EST

Prepara la confianza, envía una CSR y comprueba la identidad recibida.

Sin cambios en esta página

Esta guía es para quien implementa el cliente del dispositivo. El administrador debe haber preparado la política DMS. Para una primera ejecución completa, sigue Enrola y conecta tu primer dispositivo.

Antes de empezar

Necesitas el URL HTTPS público del DMS, la confianza del servidor obtenida por un canal aprobado, el modo de autenticación de la operación y un identificador admitido. Los ejemplos usan Bash, OpenSSL 3.x y curl con --fail-with-body; utiliza un directorio privado de trabajo y una versión compatible de esas herramientas.

Prepara est-trust.pem para verificar al servidor EST, bootstrap.crt y bootstrap.key para la autenticación inicial por certificado, y device-root.pem como raíz aprobada del emisor de dispositivos. Los dos archivos de confianza pueden contener raíces distintas. Si usas otra autenticación, adapta las credenciales según Identidad inicial.

Sustituye el host y REPLACE_DMS_ID por los de tu instalación. El APS del URL es el identificador del DMS, no su nombre visible.

Descarga e inspecciona cacerts

El contenido predeterminado es PKCS#7 DER codificado en Base64. No es un archivo PEM directo.

Comprueba las huellas, emisores y fechas frente a la política de distribución de confianza. La respuesta puede contener una selección de CAs y el certificado TLS de Lamassu. No conviertas todo el contenido en raíces confiables ni lo utilices para autenticar la misma descarga inicial. Un HTTP 200 aquí no demuestra que la autenticación ni la emisión funcionen.

Prepara la CSR

El ejemplo genera una clave EC P-256 nueva y usa est-device-001, que debe estar libre si el DMS registra automáticamente. El Common Name será el identificador del dispositivo. Comprueba que el perfil permite la clave y el sujeto elegidos.

Una implementación con hardware o almacén propio debe producir la CSR mediante su clave residente. simpleenroll envía la solicitud y conserva la clave en el cliente. Honor Extensions no autoriza todos los atributos pedidos: consulta Perfiles.

Solicita la identidad

Con autenticación inicial CLIENT_CERTIFICATE, envía la CSR DER en Base64 con Content-Type: application/pkcs10:

Detén el proceso si curl falla. Conserva el código HTTP, cabeceras y cuerpo para el diagnóstico; una respuesta de error no se decodifica como certificado. El ejemplo Bash se detiene antes de esa conversión. Un timeout deja el resultado de la operación por comprobar en Lamassu: no repitas automáticamente una emisión.

Comprueba e instala el resultado

Para el caso de una raíz que emite directamente:

Verifica además que el CN es el esperado, el certificado es final, los usos permiten tu aplicación y las fechas satisfacen el perfil. cmp debe terminar con código 0. Si hay intermedias, aporta la cadena con -untrusted según Validación PKI.

Consulta el dispositivo: DMS propietario, número de serie actual e historial deben corresponder al resultado. Guarda la pareja clave/certificado de forma protegida e instala ambos mediante el mecanismo del dispositivo. La asociación en Lamassu no instala archivos en el cliente. Comprueba una conexión real antes de considerar terminado el proceso.
