Enrolamiento con PKI

Elige la política de admisión y conecta DMS, confianza inicial y cliente EST.

Sin cambios en esta página

Enrollment with PKI reúne el recorrido desde la admisión del dispositivo hasta la instalación y renovación de su identidad. El DMS actúa como autoridad de registro: autentica la solicitud, aplica la política de registro y pide a la CA que firme. El cliente conserva o recibe la clave, instala el resultado y lo presenta al consumidor.

El recorrido

  1. El administrador prepara CA, perfil de emisión y DMS.
  2. El integrador instala confianza inicial en el servidor EST y una credencial de admisión.
  3. El cliente solicita una identidad para su Device ID mediante EST.
  4. Se comprueban certificado, vinculación al dispositivo e instalación de la pareja clave/certificado.
  5. El consumidor valida y autoriza la identidad; el cliente programa renovación y recuperación.

EST utiliza /.well-known/est/{DMS_ID}. Las APIs administrativas y la asignación manual siguen siendo recorridos distintos. Enrola y conecta un dispositivo completa una primera prueba con mTLS.

Versión del contrato

Este bloque describe el código de main examinado en el commit 8f42c47157f9a36bac3ed5caa3692aebebe19c4b. El catálogo del sitio publica main (unstable); no se atribuye este comportamiento a una release estable. Antes de utilizar otra versión, comprueba su contrato y migraciones, especialmente la autenticación independiente de reenrolamiento. Las comprobaciones de cliente y las pruebas contra una instancia se distinguen en el plan de revisión.

La configuración del Gateway, TLS, proveedores y servicios pertenece a Despliegue. El uso de la identidad en AWS u otros destinos corresponde a Integraciones.
