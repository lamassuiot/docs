Referencia de configuración

Todas las claves de configuración de Lamassu Updates, su valor por defecto, qué backend las lee y cómo sobrescribirlas con variables de entorno.

Página nueva

Lamassu Updates lee un único fichero YAML al arrancar. Esta página lista todas las claves que lee el código, su valor por defecto y qué backend (native o hawkbit) las usa. Las claves que aparecen en los ficheros de ejemplo pero no se leen se indican aparte para que no confíes en ellas.

Cómo se carga la configuración

  • Indica la ubicación del fichero con la variable de entorno OTA_CONFIG_FILE. Si no está definida, el servicio lee /etc/lamassuiot/config.yml, que es donde la imagen Docker y el chart de Helm lo montan.
  • Si OTA_CONFIG_FILE apunta a un fichero que no se puede cargar (no existe, o el YAML no es válido), el servicio registra una advertencia y recurre a /etc/lamassuiot/config.yml. En la imagen Docker esa ruta contiene el config.yml de desarrollo del repositorio, así que un error al escribir la ruta puede arrancar el servicio con una configuración equivocada. Si esa alternativa también falla, el servicio termina.
  • El fichero se lee una sola vez. Reinicia el servicio tras cualquier cambio.
  • LAMASSU_CONFIG_FILE, que definen el Dockerfile y el chart de Helm, no lo lee el código. Solo importa OTA_CONFIG_FILE.
  • Cualquier clave se puede sobrescribir con una variable de entorno. Consulta Variables de entorno.

El repositorio incluye tres ejemplos:

FicheroPara
config.ymlDesarrollo local en modo native
config-docker.ymlEl contenedor updates de docker-compose.yml
config-hawkbit.ymlDesarrollo local en modo hawkbit contra el hawkBit del fichero compose (puerto 8090 del host)

Los ejemplos contienen valores de una máquina de desarrollo (rutas absolutas y direcciones de red local) y secretos de desarrollo. Sustitúyelos todos y no reutilices nunca sus claves ni contraseñas.

Ajustes generales y del servidor

ClaveTipoPor defectoDescripción

app.logs.levelcadenainfotrace, debug, info, warn, error, fatal o none (sin distinguir mayúsculas). Un valor no reconocido se convierte en info. Con info, el registro de arranque muestra una advertencia inofensiva de «unknown log level». none descarta toda la salida de registro.

El servicio sirve siempre HTTP sin cifrar. Estas claves existen en las estructuras de configuración y en los ficheros de ejemplo pero no se leen, así que definirlas no tiene efecto: app.server.protocol, app.server.log_level, app.server.health_check (y el health_check_logging de los ejemplos), app.server.cert_file, app.server.key_file y app.server.authentication.mutual_tls.*. Termina TLS delante del servicio. Consulta Seguridad.

Base de datos

ClaveTipoPor defectoDescripción
storage.providercadenaningunoSolo existe postgres. El valor no se comprueba.
storage.hostnamecadenaninguno (obligatorio)Host de Postgres. En modo hawkbit el arranque falla si está vacío.
storage.portenteroninguno (obligatorio)Puerto de Postgres. No hay valor por defecto.
storage.username, storage.passwordcadenaningunoCredenciales.
storage.log_levelcadenainfoNivel de registro de la capa de base de datos. Las sentencias SQL se registran en trace.
  • El nombre de la base de datos está fijado en updates. No hay clave para cambiarlo. El servicio crea sus tablas y las migra al arrancar, pero no crea la base de datos: crea updates antes. En Docker Compose, init.sql crea updates y hawkbit, y POSTGRES_DB crea wfx.
  • La conexión usa sslmode=disable. No hay forma de activar TLS hacia Postgres desde la configuración. Mantén la base de datos en una red privada.
  • Cada proceso mantiene como máximo 25 conexiones abiertas y 10 inactivas (las conexiones se reciclan a los 30 minutos, o a los 5 minutos de inactividad). Calcula 25 x réplicas frente al max_connections de Postgres.

Límites de subida

ClaveTipoPor defectoDescripción
max_artifact_size_mbentero10240 (10 GiB)Mayor fichero individual subido en MiB: artefacto o .swu precompilado. Un fichero multipart mayor recibe 413 con el mensaje file "<name>" is <n> MiB; the maximum upload size is <m> MiB. El límite del cuerpo HTTP es este valor más 1 MiB. Los valores 0 o menores equivalen al valor por defecto.

Las subidas se transmiten en streaming: la memoria no crece con el fichero, pero cada subida en curso se escribe primero en un fichero temporal bajo TMPDIR (por defecto /tmp), así que necesita ese espacio libre en disco. Cualquier proxy delante del servicio debe aceptar el mismo tamaño y mantener la conexión abierta: los tiempos de lectura y escritura son de 6 horas y las conexiones inactivas se cierran a los 5 minutos. Consulta Operaciones.

Cifrado en reposo (*.encryption)

ClavePor defectoDescripción
typenonenone, local o awskms.
local_keyningunoObligatoria para local: una clave de 32 bytes codificada en hexadecimal.
awskms_key_idningunoObligatoria para awskms: ARN o alias de la clave.
awskms_regionus-east-1Región de la clave de AWS KMS.

Un objeto cifrado se cifra y descifra entero, en memoria: con cifrado en reposo, leer o escribir un artefacto de 10 GiB necesita esa misma memoria, y los rangos de bytes se cortan de la copia descifrada. Un almacén con el cifrado activado no puede usar descargas prefirmadas. Para ficheros grandes, es preferible cifrar en el propio almacén (por ejemplo, con cifrado del lado del servidor de S3).

Descargas prefirmadas (*.presign)

Con almacenamiento S3, una descarga puede responderse con 302 a una URL firmada de corta duración del almacén, en lugar de transmitir los bytes a través del servicio. Antes se autoriza al solicitante, como en cualquier descarga. El modo native firma las salidas de compilación (builds.presign); el modo hawkbit firma los objetos del plugin S3 de hawkBit (hawkbit.artifact_store.presign). Las descargas de artefactos por ID en modo native siempre se transmiten a través del servicio.

ClavePor defectoDescripción
enabledfalseActiva la función.
public_endpointel s3_endpoint del almacenamientoOrigen del almacén tal como lo alcanzan los dispositivos, sin ruta (por ejemplo, el gateway que publica el bucket). Es lo que se firma: la firma cubre la cabecera Host, así que una URL firmada para una dirección interna del clúster se rechaza cuando un dispositivo la usa a través del gateway. Obligatoria salvo que los dispositivos alcancen el almacén en su propio endpoint (por ejemplo, AWS S3).
ttl60sCuánto tiempo puede una URL iniciar una descarga. Entre 1s y 7 días. Una transferencia ya en curso no se corta al caducar.
min_remainingmin(25s, ttl/2)Una URL ya firmada para el mismo objeto se entrega de nuevo mientras le quede al menos esta validez, de modo que un reintento o una reanudación nunca recibe una URL a punto de caducar. Un valor negativo firma una URL nueva en cada petición. Debe ser menor que ttl.
access_key_id, secret_access_key (o las variantes _file)ningunoLa credencial que firma. Obligatoria, y debe ser una credencial de solo lectura distinta de la del almacenamiento.

Al arrancar, el servicio se niega a ejecutarse si la credencial de firma es la del almacenamiento, si puede escribir en el bucket (lo comprueba intentando una escritura), si el almacén la rechaza (espera hasta 2 minutos a que el almacén la acepte) o si encryption.type no es none (los dispositivos recibirían texto cifrado). Si no se puede consultar el almacén en absoluto, registra una advertencia y continúa. El dispositivo debe poder resolver y alcanzar public_endpoint. Consulta Seguridad.

Variables de entorno

Cualquier clave del fichero se puede sobrescribir con una variable de entorno: el nombre es la ruta de la clave en mayúsculas con los puntos sustituidos por guiones bajos. KMS_ENDPOINT sobrescribe kms_endpoint, STORAGE_PASSWORD sobrescribe storage.password y BUILDS_PRESIGN_TTL sobrescribe builds.presign.ttl. La clave debe existir en el fichero (basta con un valor vacío): el cargador solo considera las claves que ha leído de él.

Variables que lee el código además de estas sobrescrituras:

VariableDescripción
OTA_CONFIG_FILERuta del fichero de configuración.
POD_NAME, POD_NAMESPACEIdentidad y espacio de nombres para la elección de líder de Kubernetes. El chart de Helm las define. Si no están definidas, se usan el nombre de host y el fichero de espacio de nombres de la cuenta de servicio.
TMPDIRDónde escriben ficheros temporales las subidas y las construcciones (el directorio temporal de Go).
SERVER_PORTSolo lo usa la comprobación de salud de la imagen Docker para encontrar el puerto. Por defecto 10090.
AWS_*La cadena de credenciales por defecto de AWS, cuando un bloque S3 o AWS KMS no tiene credencial explícita.

En Docker Compose, el fichero .env lo lee docker-compose.yml, no el servicio: HOST_IP, HAWKBIT_ADMIN_PASSWORD, HAWKBIT_ARTIFACT_STORAGE y las variables HAWKBIT_ARTIFACT_S3_* y LOCAL_S3_*. Consulta .env.example en el repositorio.

El registro de depuración imprime la configuración

Con app.logs.level: debug, el servicio escribe en el registro, al arrancar, toda la configuración cargada, incluidos storage.password, encryption.local_key, las claves de S3 y hawkbit.password. En modo native, el bloque storage, contraseña incluida, también se imprime en la salida estándar en cada arranque, sea cual sea el nivel de registro. Usa info o superior donde se almacenen o compartan los registros, y guarda los secretos en un gestor de secretos, no en el fichero (consulta las credenciales *_file más arriba).

SymKMS como proceso independiente

El binario cmd/symkms ejecuta SymKMS en solitario. Su configuración solo tiene app (como arriba), symkms (un bloque de almacenamiento) y sym_keys_dir. Su directorio de claves es por defecto /data/symmetric_keys cuando no se define ni symkms.storage.local_dir ni sym_keys_dir. Sirve /symkms/v1/* pero no tiene ruta /health, y carece de autenticación igual que el monolito: consulta Seguridad.
