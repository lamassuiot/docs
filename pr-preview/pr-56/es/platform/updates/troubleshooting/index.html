Resolución de problemas

Síntomas, causas probables y soluciones para errores de arranque, llamadas a la API, construcciones, descargas y actualizaciones que no llegan a los dispositivos.

Página nueva

Diagnostica una operación cada vez. Anota el backend (GET /updates/v1/capabilities lo muestra), el endpoint, el estado HTTP y el texto err del cuerpo de la respuesta: los errores se devuelven como {"err": "..."}. Si tu problema no está aquí, consulta primero Limitaciones.

Códigos de estado HTTP

EstadoSignificado
400La petición o el estado actual del recurso no permite la operación. El mensaje indica qué cambiar.
403Una política rechaza la operación.
404El recurso no existe. El lanzamiento de otro grupo también responde 404.
409Hay una operación en conflicto en curso, o la versión ya está construida.
413Un fichero supera max_artifact_size_mb.
500Un fallo inesperado. Algunos errores de validación siguen respondiendo 500 (consulta más abajo).
501El backend activo no soporta la operación. Lee las capacidades.

Llamadas a la API

Síntoma o mensajeCausa probableSolución
501 Not ImplementedEl backend activo no soporta la operaciónLee GET /updates/v1/capabilities. En modo hawkbit, POST .../swu y .../package responden siempre 501: construye los módulos en el catálogo.
409 update pack version X is already built; create a new version ...Has cambiado una versión construidaModo native: POST .../new con {"version":"x.y.z"} mayor que la actual, vuelve a subir la sw-description (no se arrastra) y da una version mayor a cualquier artefacto que vuelvas a subir. Modo hawkbit: consulta la fila siguiente.
hawkbit mode: cannot ... here — a software module linked to a distribution set is frozen (400)En modo hawkbit se rechazan las ediciones con ámbito de paqueteDesenlaza el módulo, cámbialo y constrúyelo en el catálogo, y enlázalo de nuevo. O publica una versión nueva del módulo y crea un paquete a partir de ella con otro nombre: los nombres de paquete son únicos por grupo, y un módulo os no se puede intercambiar en un paquete existente. Consulta Modo hawkBit.
409 ... is being built or changed by another request; retry when it finishesDos construcciones, o una construcción y un cambio, sobre el mismo paquete o móduloEspera y reintenta. El bloqueo se libera cuando la operación termina o falla.
409 al crearYa existe un paquete con ese nombre en el grupoElige otro nombre.
413 file "x" is N MiB; the maximum upload size is M MiBEl fichero supera max_artifact_size_mbAuméntalo y aumenta también los límites de todos los proxies que haya delante. Consulta Operaciones. Un proxy que responde 413 con su propio cuerpo (por ejemplo el 1 MiB por defecto de nginx) es el proxy, no el servicio.
Subida 400 que menciona un contenido que contradice el nombre del ficheroUn fichero llamado .swu no es un SWUSube un .swu real, o renombra el fichero.
La subida de un artefacto falla con 500 y version X must be greater than the current latest versionLos nombres de artefacto son globales, y un nombre solo se puede reutilizar con una version mayorDa al fichero nuevo una version mayor, o un nombre de artefacto nuevo.
Cannot create launch: update pack 'x' has not been built yet (400)El paquete sigue siendo un borradorConstrúyelo primero.
Cannot create launch: update pack "x" is per-device encrypted and only N of M devices have a package (400)Algunos dispositivos no tienen claveAsigna las claves que faltan y construye de nuevo. No hay forma de forzarlo.
approval_threshold and error_threshold must be between 0 and 100Los umbrales son porcentajesUsa 0-100.
launch X is paused; resume it first (400)El lanzamiento estaba en pausaLlama a resume.
test device X cannot act as this group's canary: device X does not exist (modo hawkbit)La comprobación del canario se ejecuta antes de que los dispositivos del grupo existan en hawkBitEjecuta antes una simulación sin test_device_id (POST .../launch?dry_run=true), que registra los dispositivos como targets.
El registro de dispositivos o el KMS responde 401El servicio envía siempre X-Principal-ID: admin-mode, y el gateway intermedio lo rechazaApunta dms_endpoint y kms_endpoint a las direcciones internas de los servicios, o permite esa cabecera.

Descargas y URLs prefirmadas

Síntoma o mensajeCausa probableSolución
404 SWU not available for device D on pack "x" vNEl paquete está cifrado por dispositivo y no tiene paquete para ese dispositivo (faltaba su clave al construir, o el paquete heredó el modo por dispositivo de una versión anterior), o el fichero de la construcción ya no está en el almacénAsigna la clave del dispositivo y construye una versión nueva. Para evitar heredar, usa un paquete distinto para cada variante de cifrado (consulta Limitaciones).
Arranque: presign needs its own credentialpresign está activado sin credencial de firmaDefine presign.access_key_id[_file] y secret_access_key[_file], un par de solo lectura.
Arranque: the presign credential can WRITELa credencial de firma tiene acceso de escrituraDale una política de solo lectura sobre los objetos que sirve.
Arranque: presign signs with the storage's own credentialMisma clave que el almacenamientoCrea una clave de solo lectura aparte.
Arranque: the store does not accept the presign credentialEl almacén no conoce la clave, o la firma no coincideCrea el usuario en el almacén; revisa región y endpoint.
Arranque: presign cannot be combined with client-side encryptionencryption.type no es none en ese bloqueUsa cifrado en el almacén, o desactiva presign.
Arranque: presign.public_endpoint must be an http(s) originEl valor no tiene esquema, o tiene una rutaUsa un origen como https://updates.example.com.
El dispositivo recibe 403 del almacén tras el 302La URL caducó antes de que el dispositivo iniciara el GET, el Host firmado no es el que usó el dispositivo (public_endpoint incorrecto), la clave de firma no puede leer ese prefijo, o los relojes difierenReintenta (se emite una URL nueva por petición); revisa ttl, public_endpoint y la política de la clave.
Las descargas pasan por el servicio pese a presignUna petición HEAD, una descarga de artefacto por ID en modo native, un almacén sin presign en ese bloque, o falló la firma (queda registrado)Solo se redirigen las compilaciones en modo native y los objetos del plugin S3 en modo hawkbit.

Actualizaciones que no llegan a los dispositivos

SíntomaCausa probableSolución
Los dispositivos no pueden descargar el .swu (modo native)update_domain no es alcanzable desde el dispositivo, o no es la base completa .../updates/v1/ con barra finalUsa una dirección que el dispositivo pueda resolver. El valor por defecto del chart de Helm carece de /updates.
Modo hawkbit: un dispositivo recibe 401 del DDIhawkBit rechaza a los dispositivos que no se autenticanHabilita y usa un autenticador de dispositivos de hawkBit. Consulta Modo hawkBit.
Modo hawkbit: un dispositivo recibe 429El filtro DoS propio de hawkBit, que limita la frecuencia con que un dispositivo puede llamarloReduce la frecuencia de consulta y de informes de estado del dispositivo.
Modo hawkbit: el lanzamiento permanece running sin avanzarLos dispositivos nunca contactaron con hawkBit, o consultan otro hawkBitComprueba qué hawkBit consultan los dispositivos y que los targets existen. Un grupo de rollout no puede avanzar hasta que sus dispositivos consultan.
Modo hawkbit: no se encuentran dispositivos en el grupodms_endpoint no está definido, así que los grupos son las etiquetas de target group:<id>Define dms_endpoint, o etiqueta los targets.
Un lanzamiento phased se queda en CREATED (modo native)En el workflow phased algunos pasos los hace WFX o un operadorConfírmalos mediante WFX, o usa direct.
Un lanzamiento non-swu muestra estados de SWU (modo native)Se creó con workflow_type: directUsa download-install.
El dispositivo instala y muestra la versión antiguaNo se cambió la versión de la cargaSube la versión antes de construir.
El dispositivo ignora los despliegues nuevosSWUpdate conserva como pendiente de prueba (ustate=1) el estado de actualización de una instalación anterior y rechaza una nuevaConfirma o restablece el estado de actualización del dispositivo. Es un ajuste del dispositivo, no del servicio.
El dispositivo rechaza el .swu y el error menciona descifrado o imagen no válidaEl .swu no está firmado y el dispositivo exige firma, o la firma no es CMSFírmalo con un KMS que devuelva CMS. Un fallo de firma puede notificarse como error de cifrado.
El dispositivo no logra descifrarLa clave usada al construir difiere de la del dispositivo, o difiere la grafía del algoritmoUsa la misma clave y el mismo algoritmo. Revisa la asignación en SymKMS.

Escalado y trabajo en segundo plano

SíntomaCausa probableSolución
Los pods no pueden arrancar en nodos distintosEl volumen ReadWriteOnce (ambos modos mientras persistence.enabled es true)Define persistence.enabled: false y pasa artifacts, builds y symkms a S3. Consulta Operaciones.
Los lotes de campaña nunca avanzan (modo native)Falla la elección de líder, o no llegan los eventos de WFXRevisa los Leases y el RBAC, o define leaderElection.mode: database. La línea de registro leadership acquired aparece en el líder.
Los lanzamientos programados nunca empiezan (modo native)El mismo trabajo en segundo plano, que se ejecuta en el líderIgual que arriba.
Las construcciones por dispositivo son lentasEl límite de CPUSúbelo. Consulta Dimensionado de recursos.
El pod muere durante una subida o una construcción cifradaLímite de memoria, o el disco temporal está llenoDimensiona la memoria para el mayor fichero que cifres y da margen a TMPDIR.

Obtener más información

  • Sube app.logs.level a debug, pero recuerda que imprime secretos.
  • GET /updates/v1/capabilities muestra el backend activo y lo que soporta.
  • Cada réplica registra cuál lidera (leadership acquired, is the leader, standing by).
  • En modo hawkbit, inspecciona lo que creó el servicio mediante la API de gestión de hawkBit (puerto 8090 en Compose, con las credenciales Basic Auth de la configuración). Cada instancia de hawkBit tiene sus propios datos: consulta la que indica hawkbit.base_url.
