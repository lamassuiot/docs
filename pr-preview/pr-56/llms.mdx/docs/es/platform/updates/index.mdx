# Lamassu Updates (/docs/pr-preview/pr-56/es/platform/updates/overview)



<div className="lm-diff-ins lm-diff-block">
  Lamassu Updates (también llamado OTA Update Service) orquesta las actualizaciones de software por aire (OTA) de flotas IoT. Publicas una actualización, eliges qué dispositivos la reciben y sigues el despliegue. El servicio construye el paquete que instalan los clientes [SWUpdate](https://swupdate.org/) y puede firmarlo y cifrarlo.
</div>

<div className="lm-diff-ins lm-diff-block">
  Hay una única API HTTP y dos backends intercambiables detrás de ella, que se eligen con el ajuste `mode`. El backend decide con qué servidor de actualizaciones hablan los dispositivos, así que los sistemas que rodean al servicio dependen de él.
</div>

<div className="lm-diff-ins lm-diff-block">
  Con qué se conecta [#con-qué-se-conecta]
</div>

<div className="lm-diff-ins lm-diff-block">
  | Sistema                                             | Qué hace                                                                                                                                                  | `native`     | `hawkbit`                                                                                            |
  | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------- |
  | [Lamassu IoT](/docs/platform/iot-fleets/overview)   | Registro de dispositivos (grupos de dispositivos) y KMS. Las claves de firma viven en su KMS                                                              | Obligatorio  | Opcional: sin él, los grupos se leen de las etiquetas `group:<id>` de los targets del propio hawkBit |
  | [WFX](https://github.com/siemens/wfx)               | Orquestación de trabajos. Cada actualización de un dispositivo es un trabajo (job) de WFX que el dispositivo consulta                                     | Obligatorio  | No se usa                                                                                            |
  | [Eclipse hawkBit](https://www.eclipse.org/hawkbit/) | Servidor de actualizaciones. Almacena paquetes, módulos y rollouts, y los dispositivos lo consultan                                                       | No se usa    | Obligatorio                                                                                          |
  | Postgres                                            | Los datos propios del servicio                                                                                                                            | Obligatorio  | Obligatorio                                                                                          |
  | swugenerator                                        | Herramienta Python, incluida en el [repositorio ota](https://github.com/lamassuiot/ota), que ensambla el fichero `.swu` firmado y, opcionalmente, cifrado | Al construir | Al construir                                                                                         |
</div>

<div className="lm-diff-ins lm-diff-block">
  El dashboard de Lamassu es la interfaz web de esta API. Lee su URL base de `LAMASSU_UPDATES_API` en `public/config.js` (si no está definida, usa la URL base de la API principal) y añade él mismo `/updates/v1` y `/symkms/v1`. También lee una vez `GET /updates/v1/capabilities` y oculta las funciones que el backend activo no soporta.
</div>

<div className="lm-diff-ins lm-diff-block">
  Elige tu backend [#elige-tu-backend]
</div>

<div className="lm-diff-ins lm-diff-block">
  La API HTTP es la misma en ambos casos. Lo que cambia es quién almacena los datos y con quién hablan los dispositivos.
</div>

<div className="lm-diff-ins lm-diff-block">
  |                                            | `native` (por defecto)                                                    | `hawkbit`                                                                     |
  | ------------------------------------------ | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
  | Almacena paquetes, lanzamientos y trabajos | El Postgres de este servicio, más WFX                                     | Un servidor Eclipse hawkBit                                                   |
  | Los dispositivos consultan                 | WFX                                                                       | hawkBit (API DDI)                                                             |
  | Un paquete se construye                    | Entero, a partir de los ficheros de todos sus módulos, en un único `.swu` | Un `.swu` (o entregable raw) por módulo, construido en el catálogo de módulos |
  | Cifrado por dispositivo                    | Soportado                                                                 | No soportado                                                                  |
  | Elígelo cuando                             | Empiezas de cero, o necesitas cifrado por dispositivo                     | hawkBit ya es el backend de actualizaciones de tu flota                       |
</div>

<div className="lm-diff-ins lm-diff-block">
  Se configura con el campo `mode` de la [configuración](/docs/platform/updates/reference/configuration). Los backends no son equivalentes en todas las funciones: consulta [Capacidades](/docs/platform/updates/reference/capabilities) y [Modo hawkBit](/docs/platform/updates/hawkbit-mode).
</div>
