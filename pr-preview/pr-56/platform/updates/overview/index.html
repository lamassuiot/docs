Lamassu Updates

What the service does, how it fits with Lamassu IoT, WFX and hawkBit, and where to start.

Página nueva

Lamassu Updates (also called the OTA Update Service) orchestrates over-the-air software updates for IoT fleets. You publish an update, choose which devices receive it, and watch the rollout. The service builds the package that SWUpdate clients install, and can sign and encrypt it.

There is one HTTP API and two interchangeable backends behind it, chosen with the mode setting. The backend decides which update server the devices talk to, so the systems around the service depend on it.

The Lamassu dashboard is the web interface for this API. It reads its base URL from LAMASSU_UPDATES_API in public/config.js (when unset it falls back to the main API base URL) and appends /updates/v1 and /symkms/v1 itself. It also reads GET /updates/v1/capabilities once and hides the features the active backend does not support.

Choose your backend

The HTTP API is the same either way. What differs is who stores the data and who the devices talk to.

native (default)hawkbit
Stores packs, launches, jobsThis service's Postgres, plus WFXAn Eclipse hawkBit server
Devices pollWFXhawkBit (DDI API)
A pack is builtAs a whole, from all its modules' files, into one .swuOne .swu (or raw deliverable) per module, built in the module catalog
Per-device encryptionSupportedNot supported
Pick it whenYou start from scratch, or need per-device encryptionhawkBit is already your fleet's update backend

Set it with the mode field of the configuration. The backends are not equivalent in every feature: see Capabilities and hawkBit mode.
