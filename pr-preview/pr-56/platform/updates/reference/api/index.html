API reference

Every route of the Lamassu Updates and SymKMS HTTP APIs, with request bodies, status codes and per-backend behaviour.

Página nueva

Reference for the HTTP API of Lamassu Updates, as implemented by the service in internal/updates/httpapi (shared by the native and hawkBit backends). Use it to look up a route, a body field or a status code. For worked examples, follow the native or hawkBit curl guide.

Conventions

The Updates API is served under /updates/v1, and SymKMS under /symkms/v1. Paths in this page are relative to /updates/v1 unless they begin with /health or /symkms. Behind the Lamassu gateway the prefix is typically /api/updates/v1, which is what the dashboard calls.

:groupID is a Lamassu device group. :name is a pack name. :moduleKey is type:name (for example os:water-panel), literal or percent-encoded. In paths a pack is a distribution-sets resource (see Concepts).

TopicBehaviour
BodiesJSON, except uploads, which are multipart/form-data with the file in the field file
ErrorsThe body is {"err":"<message>"}
HealthGET /health returns {"status":"ok"}, outside /updates/v1
AuthenticationNone in the service: it does not authenticate callers. In a Lamassu deployment the gateway in front of it does. See Security
Upload limitOne file can be up to max_artifact_size_mb MiB, 10240 (10 GiB) by default. A larger file answers 413
TimeoutsA request can read or write for up to 6 hours; an idle connection is closed after 5 minutes. Uploads are streamed to disk, not held in memory
CORSAny origin and any request header are allowed

The ingress or gateway in front of the service needs its own limits raised to match: see Configuration.

Status codes

CodeMeaning
200Success
201Created: packs, modules, launches, standalone artifact uploads
202Accepted: sync-to-latest and force-version
204Deleted, with no body: artifacts, staged files, latest-version records, module files
206, 416Partial content, or an unsatisfiable range, on downloads
207sync-to-latest dispatched some devices and failed others
302A download redirected to a short-lived signed URL
400Invalid input, or an operation not valid in the current state (for example changing a built pack's module composition)
403Forbidden by policy (for example downloading a previous version that the pack does not allow)
404The resource does not exist
409Conflict: the pack version is already built (artifact upload, link or prebuilt upload), the pack name already exists, or another request is working on the same resource
413An uploaded file is over the size limit
501The active backend does not support the operation. See Capabilities

Downloads

Download routes stream the file and support resuming:

  • HEAD works on every download route and returns the size and Accept-Ranges: bytes.
  • Range: bytes=... with a single range answers 206 with Content-Range. A range that cannot be satisfied answers 416. A request with several ranges is answered with the whole file.
  • With S3 storage and presigning enabled, a GET can answer 302 to a signed URL of the object store, with Cache-Control: no-store. The caller is authorized first; the store then only checks the signature. A HEAD is never redirected. Native mode signs build outputs (.swu and packages); hawkBit mode signs the objects of hawkBit's S3 artifact plugin. If signing fails, the service streams the file instead.
  • Content-Disposition: attachment carries the file name.

List endpoints

Routes that return collections share these query parameters:

ParameterMeaning
page_sizeItems per page. Default 25, at most 500
bookmarkOpaque cursor from the previous page
sort_by, sort_modeA filterable field, and asc (default) or desc. A sort_by that is not a filterable field is ignored
filterfield[operand]value, repeatable

Filter operands depend on the field type:

Field typeOperands
Stringeq, ne, ct (contains), nc (not contains), each with an _ic variant for case-insensitive matches
Datebf (before), eq, af (after)
Numbereq, ne, lt, le, gt, ge
Enumeq, ne

For example GET /groups/g1/distribution-sets?filter=name[ct]firmware&sort_by=name&sort_mode=desc.

Paginated lists return {"next": "<bookmark>", "list": [...]}. Pass next as bookmark to get the next page; next is empty on the last page. Filterable fields per list:

ListFilterable fields
Packs: .../distribution-sets, /distribution-setsgroup_id, name, version, packaging (enum), created_at
Launches: /groups/:groupID/launchgroup_id, status (enum), workflow_type, created_at, distribution_set_id
Version snapshots: .../versions, /distribution-sets/:id/versionsversion (number), created_at
Fleet artifact catalog: GET /artifactsname, version, checksum, uploaded_at
Device pack versions and inventory: /devices/distribution-sets, /devices/:deviceID/distribution-sets, .../distribution-set-inventorydevice_id, distribution_set_id, distribution_set_name, group_id, version (number), packaging (enum), installed_at
Device update history: /devices/:deviceID/distribution-set-updates, /devices/distribution-set-updates/latestdevice_id, group_id, distribution_set_name, distribution_set_id, launch_id, job_id, status (enum), packaging (enum), source
Latest versions: .../latest-distribution-setsgroup_id, distribution_set_id, distribution_set_name, version (string), updated_at

Some lists do not page or filter:

  • The job lists (/groups/:groupID/device/:deviceID/jobs, .../history, /launch/:launchID/jobs) honour only page_size and bookmark. The bookmark is a numeric offset.
  • The module lists, /updatable-distribution-sets, the pack-scoped .../artifact-catalog, /version-compliance, /version-status and /workflows return everything.
  • GET /devices/distribution-set-updates/latest returns everything, after applying the filters.
  • In hawkBit mode no list is paged (next is always empty). Only the fleet-wide /devices/distribution-sets and /devices/distribution-set-updates/latest apply filter.

Some routes exist in only one backend, or behave differently. Check Capabilities first.

Request bodies

RouteBody
Create packRequired: name, version (semver x.y.z), group_id. Optional: type (rawfile or firmware), packaging (swu, the default, or non-swu), allow_previous_version_download, modules, preconditions. Each modules entry is a new module (type, name, optional version and delivery_intent) or an existing one (source_module_id). hawkBit mode accepts only source_module_id entries, of built modules
POST .../new{"version":"x.y.z"}: semver, and greater than the current version, or 400
PUT .../preconditions{"preconditions":[{"required_distribution_set_name":"...","min_version":"1.2.0"}]}. Use required_module_key (type:name) instead of the pack name to target a module. Exactly one of the two per entry, and min_version must be x.y.z. A device must satisfy every entry
POST .../swu, .../packageuser, encryption_key_name, encryption_alg_name, sw_desc_encrypted, signature_key_id, signature_alg_name, signature_certificate (PEM), selected_artifact_ids. All optional, but user is required with encryption_key_name. A body with encryption_alg_name only requests per-device encryption. An empty or invalid body builds without encryption. See Signing and encryption

Artifacts reach a build only through selected_artifact_ids; without them there is normally nothing staged and the build fails. A build replaces the pack's carried artifact links with the selected ones.

Responses

  • Create routes answer 201 with the object: a pack, a module, or for a launch the launch ID and the precondition outcome. modules is an input of pack creation and is not returned on reads.
  • DELETE of a pack answers 200 with {"message": "..."}. POST .../new, .../swu and .../package answer 200 with {"message": "..."}.
  • Artifact uploads answer {"msg": "...", "artifact": {...}}: 201 for POST /artifacts, 200 for the pack-scoped and module-scoped uploads.
  • Descriptor uploads on a pack or on a module in a pack answer {"msg": "..."}.
  • Module lists answer {"modules": [...]}. The pack-scoped .../artifacts list answers a bare array.
  • A failed build leaves the pack in status build_failed, with the reason in last_build_error. It is editable and can be built again.

Launch

A launch carries id, group_id, name, description, version, exec_date, scheduled_at, status, the strategy fields (workflow_type, rollout_type, rollout_value, test_device_id, auto, approval_threshold, error_threshold, weight), distribution_set_id, distribution_set_name, the counters pending_count, active_count, completed_count, failed_count, total_devices, completed_in_batch, test_device_status, aborted, forced_preconditions and precondition_failures.

status is running (empty on a native launch that has not changed state yet, which also means running), paused, cancelled or completed. test_device_status is pending, active, completed, failed or cancelled.

Artifact

id, name, version, filename, checksum (SHA-256 of the file), size in bytes and uploaded_at. The fleet-wide list adds distribution_sets: the packs that reference it, each with distribution_set_id, distribution_set_name, distribution_set_version and group_id. A file whose name ends in .swu or .tar.gz must look like one, or the upload answers 400.

Software module catalog

Modules that exist independently of any pack. Create one with POST /softwaremodules, giving type, name, version and optionally delivery_intent (default undecided). Use the returned id for the by-id routes.

MethodPathDescription
GET/softwaremodulesFleet-wide catalog, with the source pack
POST/softwaremodulesDeclare a module with no pack yet. Answers 201. type, name and version are required
DELETE/softwaremodules/:moduleKey/versions/:versionDelete a module that no pack holds. 400 if a pack still holds it
GET/softwaremodules/by-id/:moduleIDRead one module
PUT/softwaremodules/by-id/:moduleIDUpdate delivery_intent and release_notes. Send at least one
POST/softwaremodules/by-id/:moduleID/artifactsUpload a file (field file). Answers 201 with the artifact
GET/softwaremodules/by-id/:moduleID/artifacts/:artifactID/downloadDownload a stored file
DELETE/softwaremodules/by-id/:moduleID/artifacts/:artifactIDRemove a file. Answers 204
POST/softwaremodules/by-id/:moduleID/descriptorUpload the sw-description the build reads (field file). Answers the module
POST/softwaremodules/by-id/:moduleID/buildBuild this module's deliverable. hawkBit mode only (501 in native). Behaviour depends on delivery_intent. The body is optional and takes user, encryption_key_name, encryption_alg_name, sw_desc_encrypted, signature_key_id, signature_alg_name, signature_certificate

Files are accepted while the delivery is undecided. A swu-build module takes build inputs and refuses a .swu; a swu-prebuilt module takes exactly one .swu. Choose a compatible delivery intent before importing the module with source_module_id. Once a module has shipped (a released pack version holds it, or hawkBit locked it) it is locked: its content is protected, while release notes stay editable. In native mode the pack builds one .swu from every module's inputs, and a prebuilt SWU is uploaded to the whole pack rather than imported as a module input.

Create body:

FieldRequiredMeaning
distribution_set_nameYesThe pack to launch. It must be built
workflow_typeYesdirect or phased. The full WFX names (wfx.workflow.dau.direct) are accepted. hawkBit mode: phased makes a soft action, anything else a forced one

The strategy update body takes workflow_type, rollout_type, rollout_value (greater than 0), test_device_id, auto, approval_threshold and error_threshold. It replaces all of them: an omitted field resets to its zero value, so send the whole strategy.

A create answers 201 with launch_id, precondition_failures, forced, superseded_devices and never_seen_devices. A dry run answers 200 with qualifying_devices, precondition_failures, superseded_devices and never_seen_devices. The last two are filled only in hawkBit mode: devices with an update in flight, which creating the launch cancels, and devices that have never contacted hawkBit.

A launch is refused with 400 when the pack is not built, or when a per-device encrypted pack has devices without a package (dry runs included, and force_preconditions does not override it).

Version compliance and latest versions

Declare the version devices should be on, then report and correct drift.

MethodPathDescription
GET/groups/:groupID/latest-distribution-setsA group's declared latest versions
PUT/groups/:groupID/latest-distribution-sets/:distributionSetIDDeclare a pack's latest version (body {"version":"1.2.0"})
DELETE/groups/:groupID/latest-distribution-sets/:distributionSetIDRemove the declaration. Answers 204
GET/devices/:deviceID/latest-driftA device's drift from its group's latest versions. Optional ?groupID=
POST/devices/:deviceID/sync-to-latestForce the device to match. Answers 202 with the drift
POST/devices/:deviceID/force-versionLaunch one device to a version. Answers 202
GET/groups/:groupID/version-complianceDevices not on the latest version, as {"group_id", "devices": [...]}
GET/groups/:groupID/version-statusThe full per-device matrix, compliant and outdated, as {"group_id", "rows": [...]}

sync-to-latest takes an optional body with groupID (also accepted as ?groupID=), distribution_set_ids to limit the packs and workflow. If some devices could not be dispatched it answers 207, or 400 when none were, with {"err": "...", "drift": {...}}.

force-version takes distribution_set_id and version (required), group_id and workflow. The device must be a member of the pack's group. For a swu pack workflow defaults to phased, and for a non-swu pack to download-install. Native mode accepts only the pack's current version unless the pack has allow_previous_version_download, and sync-to-latest has the same limit. hawkBit mode ignores workflow in both routes.

A drift entry has distribution_set_id, distribution_set_name, current_version, latest_version, in_sync and missing. A version-status row has device_id, distribution_set_id, distribution_set_name, current_version, latest_version, in_sync and, when newer than the declared one, newest_version.

Device artifact download, hawkBit mode

In hawkBit mode the service also serves hawkBit's device artifact URL, so a gateway can publish it on the same host as the rest of the API:

MethodPathDescription
GET, HEAD<prefix>/:tenant/controller/v1/:controllerId/softwaremodules/:softwareModuleId/artifacts/:filenameA module's artifact, or its .MD5SUM sidecar as text/plain

<prefix> is the path of hawkbit.ddi_url, for example /api/hawkbit-ddi. The route is registered only in hawkBit mode. It answers only for modules in the device's assigned or installed set, and 404 otherwise, and :tenant must be the configured tenant. With presigning enabled it answers 302 like the other downloads.

SymKMS

Served at /symkms/v1 by the same process when SymKMS is configured. It stores symmetric keys and binds them to devices. The encrypt, decrypt and MAC bodies and formats are in Signing and encryption. Errors use the same {"err":"..."} body.

An empty purpose is a wildcard that matches any lookup, and a specific purpose is matched exactly. The routes that return raw key material trust the gateway to authenticate callers: do not expose them without mTLS or scoped tokens. See Security.
