Configuration reference

Every configuration key of Lamassu Updates, its default, which backend reads it, and how to override it with environment variables.

Página nueva

Lamassu Updates reads a single YAML file at start-up. This page lists every key the code reads, its default, and which backend (native or hawkbit) uses it. Keys that appear in the example files but are not read are listed separately so you do not rely on them.

How the configuration is loaded

  • Set the file location with the OTA_CONFIG_FILE environment variable. If it is unset, the service reads /etc/lamassuiot/config.yml, which is where the Docker image and the Helm chart mount it.
  • If OTA_CONFIG_FILE names a file that cannot be loaded (missing, or invalid YAML), the service logs a warning and falls back to /etc/lamassuiot/config.yml. In the Docker image that path holds the repository's developer config.yml, so a typo in the path can start the service with the wrong settings. If the fallback fails too, the service exits.
  • The file is read once. Restart the service after any change.
  • LAMASSU_CONFIG_FILE, which the Dockerfile and the Helm chart set, is not read by the code. Only OTA_CONFIG_FILE matters.
  • Any key can be overridden by an environment variable. See Environment variables.

The repository ships three examples:

FileFor
config.ymlLocal development in native mode
config-docker.ymlThe updates container of docker-compose.yml
config-hawkbit.ymlLocal development in hawkbit mode against the hawkBit of the compose file (host port 8090)

The examples contain values for one developer machine (absolute paths and LAN addresses) and development secrets. Replace all of them, and never reuse their keys or passwords.

General and server settings

KeyTypeDefaultDescription
modestringempty (native)native or hawkbit. See hawkBit mode.
app.logs.levelstringinfotrace, debug, info, warn, error, fatal or none (case-insensitive). An unrecognised value becomes info. At info the start-up log prints a harmless "unknown log level" warning. none discards all log output.
app.server.listen_addressstringempty (all interfaces)Address to bind. The examples use 0.0.0.0.
app.server.portintegernone (required)HTTP port. 0 picks a random port. The examples and the chart use 10090.
app.server.shutdown_timeoutduration60sHow long to wait for in-flight requests after SIGTERM or SIGINT. Keep it below the termination grace period of the pod (the chart sets 120 s).
enable_test_endpointsbooleanfalseRegisters PUT /updates/v1/jobs/:jobID/transition, which forges a job state change without ownership checks. Use only in tests; keep it false anywhere else.

The service always serves plain HTTP. These keys exist in the configuration structs and in the example files but are not read, so setting them has no effect: app.server.protocol, app.server.log_level, app.server.health_check (and the health_check_logging of the examples), app.server.cert_file, app.server.key_file and app.server.authentication.mutual_tls.*. Terminate TLS in front of the service. See Security.

Database

KeyTypeDefaultDescription
storage.providerstringnoneOnly postgres exists. The value is not checked.
storage.hostnamestringnone (required)Postgres host. In hawkbit mode startup fails if it is empty.
storage.portintegernone (required)Postgres port. There is no default.
storage.username, storage.passwordstringnoneCredentials.
storage.log_levelstringinfoLog level of the database layer. SQL statements are logged at trace.
  • The database name is fixed to updates. There is no key for it. The service creates its tables and migrates them at start-up, but it does not create the database: create updates first. In Docker Compose, init.sql creates updates and hawkbit, and POSTGRES_DB creates wfx.
  • The connection uses sslmode=disable. There is no way to enable TLS towards Postgres from the configuration. Keep the database on a private network.
  • Each process keeps at most 25 open and 10 idle connections (connections are recycled after 30 minutes, or 5 idle minutes). Budget 25 x replicas against the max_connections of Postgres.

Endpoints of other services

KeyDefaultModeDescription
dms_endpointnoneRequired in native, optional in hawkbitBase URL of the Lamassu Device Manager API, for example http://host:8080/api/devmanager. It is the source of device groups. Without it in hawkbit mode, groups are read from the group:<id> tags of the hawkBit targets. The service sends X-Principal-ID: admin-mode on these calls.
kms_endpointnoneBothBase URL of the Lamassu KMS API, for example http://host:8080/api/kms/v1. Needed to sign. See Signing and encryption.
symkms_endpointnoneBothBase URL of SymKMS, without the /symkms/v1 path. In the monolith it points at the service itself (for example http://localhost:10090) and must match app.server.port. Empty means encryption is refused.
wfx_endpointnonenativeBase URL of the WFX management API (port 8081 inside the Compose network, 9081 on the host). The service appends /api/wfx/v1/. Startup fails if WFX cannot be reached. Devices use the WFX client port instead.
update_domainnonenativePublic base URL devices use to download builds, for example http://updates:10090/updates/v1/. It must end in /updates/v1/, with the trailing slash: the service appends groups/... directly and stores the result as the pack URI. It must be reachable from the devices.

build_memory_limit_mb0 (no check)hawkbitRefuses a build that would encrypt a file in memory (about twice its size) above this limit, in MiB, before the process is killed for lack of memory.

Upload limits

KeyTypeDefaultDescription
max_artifact_size_mbinteger10240 (10 GiB)Largest single uploaded file in MiB: artifact or prebuilt .swu. A larger multipart file gets 413 with the message file "<name>" is <n> MiB; the maximum upload size is <m> MiB. The HTTP body limit is this value plus 1 MiB. Values of 0 or less mean the default.

Uploads are streamed: memory does not grow with the file, but each in-flight upload is written to a temporary file under TMPDIR (default /tmp) first, so it needs that much free disk. Any proxy in front of the service must accept the same size and keep the connection open: read and write timeouts are 6 hours and idle connections are closed after 5 minutes. See Operations.

At-rest encryption (*.encryption)

KeyDefaultDescription
typenonenone, local or awskms.
local_keynoneRequired for local: a hex-encoded 32-byte key.
awskms_key_idnoneRequired for awskms: key ARN or alias.
awskms_regionus-east-1Region of the AWS KMS key.

An encrypted object is encrypted and decrypted whole, in memory: with at-rest encryption, reading or writing a 10 GiB artifact needs that much memory, and byte ranges are cut from the decrypted copy. A store with encryption enabled cannot use presigned downloads. For large files, prefer encrypting at the store (for example S3 server-side encryption) instead.

Presigned downloads (*.presign)

With S3 storage, a download can be answered with 302 to a short-lived signed URL of the store instead of streaming the bytes through the service. The caller is authorized first, as for any download. Native mode signs build outputs (builds.presign); hawkbit mode signs the objects of hawkBit's S3 plugin (hawkbit.artifact_store.presign). Artifact downloads by ID in native mode are always streamed.

KeyDefaultDescription
enabledfalseTurns the feature on.
public_endpointthe storage s3_endpointOrigin of the store as devices reach it, without a path (for example the gateway that publishes the bucket). It is what gets signed: the signature covers the Host header, so a URL signed for an in-cluster address is refused when a device fetches it through the gateway. Required unless devices reach the store at its own endpoint (for example AWS S3).
ttl60sHow long a URL can start a download. Between 1s and 7 days. A transfer already under way is not cut when it expires.
min_remainingmin(25s, ttl/2)A URL already signed for the same object is handed out again while it has at least this much validity left, so a retry or resume never gets a URL about to expire. Negative signs a fresh URL on every request. Must be lower than ttl.
access_key_id, secret_access_key (or the _file variants)noneThe credential that signs. Required, and it must be a read-only credential different from the storage one.

At start-up the service refuses to run when the signing credential is the storage credential, when it can write to the bucket (it probes with a write), when the store rejects it (it waits up to 2 minutes for the store to accept it), or when encryption.type is not none (devices would receive ciphertext). If the store cannot be asked at all, it logs a warning and continues. The device must still be able to resolve and reach public_endpoint. See Security.

hawkbit block

Used only when mode: hawkbit.

KeyDefaultDescription
hawkbit.base_urlnone (required)hawkBit Management API root, for example http://hawkbit:8080. Startup fails if it is empty. Calls time out after 30 s; artifact transfers after 6 h.
hawkbit.username, hawkbit.passwordnoneManagement API Basic Auth credentials.
hawkbit.tenantDEFAULTDDI tenant path segment.
hawkbit.ddi_urlhawkbit.base_urlhawkBit's DDI root as devices reach it (for example https://updates.example.com/api/hawkbit-ddi). It is used to build the download URLs devices receive, and its path becomes the prefix of the DDI download route this service serves.
hawkbit.artifact_storenoneSame shape as the blob storage blocks: storage must point to the bucket and s3_prefix of hawkBit's S3 artifact plugin, and presign enables signed downloads. Without it, artifacts are streamed through hawkBit.

The storage (Postgres) block is also required in hawkbit mode.

Environment variables

Any key of the file can be overridden by an environment variable: the name is the key path in upper case with dots replaced by underscores. KMS_ENDPOINT overrides kms_endpoint, STORAGE_PASSWORD overrides storage.password and BUILDS_PRESIGN_TTL overrides builds.presign.ttl. The key must exist in the file (an empty value is enough): the loader only considers keys it has read from it.

Variables the code reads besides these overrides:

VariableDescription
OTA_CONFIG_FILEConfiguration file path.
POD_NAME, POD_NAMESPACEIdentity and namespace for Kubernetes leader election. The Helm chart sets them. If unset, the hostname and the service-account namespace file are used.
TMPDIRWhere uploads and builds write temporary files (Go's temporary directory).
SERVER_PORTUsed only by the health check of the Docker image to find the port. Default 10090.
AWS_*The AWS default credential chain, when an S3 or AWS KMS block has no explicit credential.

For Docker Compose, the .env file is read by docker-compose.yml, not by the service: HOST_IP, HAWKBIT_ADMIN_PASSWORD, HAWKBIT_ARTIFACT_STORAGE and the HAWKBIT_ARTIFACT_S3_* and LOCAL_S3_* variables. See .env.example in the repository.

Debug logging prints the configuration

With app.logs.level: debug, the service writes the whole loaded configuration to the log at start-up, including storage.password, encryption.local_key, S3 keys and hawkbit.password. In native mode the storage block, password included, is also printed to standard output at every start, whatever the log level. Use info or higher anywhere logs are stored or shared, and keep secrets in a secret store, not in the file (see the *_file credentials above).

SymKMS as its own process

The cmd/symkms binary runs SymKMS alone. Its configuration has only app (as above), symkms (a storage block) and sym_keys_dir. Its key directory defaults to /data/symmetric_keys when neither symkms.storage.local_dir nor sym_keys_dir is set. It serves /symkms/v1/* but no /health route, and it has the same lack of authentication as the monolith: see Security.
