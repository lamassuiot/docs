Troubleshooting

Symptoms, likely causes and fixes for start-up errors, API calls, builds, downloads and updates that do not reach devices.

Página nueva

Diagnose one operation at a time. Note the backend (GET /updates/v1/capabilities shows it), the endpoint, the HTTP status and the err text of the response body: errors are returned as {"err": "..."}. If your problem is not here, check Limitations first.

HTTP status codes

StatusMeaning
400The request or the current state of the resource does not allow the operation. The message says what to change.
403A policy refuses the operation.
404The resource does not exist. Another group's launch also answers 404.
409A conflicting operation is in progress, or the version is already built.
413A file is larger than max_artifact_size_mb.
500An unexpected failure. Some validation errors still answer 500 (see below).
501The active backend does not support the operation. Read the capabilities.

Starting the service

Symptom or messageLikely causeFix
docker compose up fails with a network errorThe ota-net network does not existdocker network create ota-net
Docker build cannot find lamassuiot/coreThe build context is not the parent of the checkoutBuild with the context that contains ota/, lamassuiot/core and lamassuiot/sdk. docker compose build updates uses it.
The service ignores OTA_CONFIG_FILE and logs a warningThe file could not be loaded, so it fell back to /etc/lamassuiot/config.ymlCheck the path and the YAML. In the image the fallback is the repository's developer configuration.
workflow_file "..." must contain "direct"workflow_file does not name the direct workflowPoint it at wfx.workflow.dau.direct.yml or a path containing direct.
failed to list existing WFX workflowswfx_endpoint is wrong or WFX is downUse the management port (8081 inside the Compose network, 9081 on the host) and check that custom-wfx runs.
Postgres reports that database updates does not existThe database is not created by the serviceCreate it (Docker Compose does it through init.sql).
mode is "hawkbit" but hawkbit.base_url is not configuredMissing keySet hawkbit.base_url.
mode is "hawkbit" but storage (Postgres) is not configuredstorage.hostname is emptySet the storage block.
S3 bucket "x" is not accessible at ...Wrong bucket, endpoint or credentials, or the bucket does not existFix the s3_* keys of the block named in the error. The bucket must already exist.
local encryption key must be exactly 32 bytesencryption.local_key is not 32 bytes of hexUse 64 hex characters (openssl rand -hex 32).
could not configure leader election: the service account may not ... LeasesThe pod cannot use Leases and leaderElection.mode is kubernetesGrant the Role the chart provides (serviceAccount.create: true), or set leaderElection.mode: database.
not running inside a Kubernetes clusterleader_election.mode: kubernetes outside a clusterUse empty (auto) or database.
builds.presign: ... or hawkbit.artifact_store.presign: ...The presigned-download settings of that block are invalidSee Downloads and presigned URLs.
The hawkBit container exitsS3 storage is selected for hawkBit and the bucket is unreachableFix the S3 settings, or use HAWKBIT_ARTIFACT_STORAGE=fs. hawkBit never falls back to local disk silently.
/health answers but WFX calls fail/health does not check dependenciesCheck wfx_endpoint and that WFX is running.
Debug output shows secretsapp.logs.level: debug prints the configurationUse info. See Security.

API calls

Symptom or messageLikely causeFix
501 Not ImplementedThe active backend does not support the operationRead GET /updates/v1/capabilities. In hawkbit mode, POST .../swu and .../package always answer 501: build the modules in the catalog.
409 update pack version X is already built; create a new version ...You changed a built versionNative mode: POST .../new with {"version":"x.y.z"} greater than the current one, then upload the sw-description again (it is not carried over) and give any re-uploaded artifact a higher version. hawkbit mode: see the next row.
hawkbit mode: cannot ... here — a software module linked to a distribution set is frozen (400)Pack-scoped edits are refused in hawkbit modeUnlink the module, change and build it in the catalog, link it again. Or release a new version of the module and create a pack from it under another name: pack names are unique per group, and an os module cannot be swapped on an existing pack. See hawkBit mode.
409 ... is being built or changed by another request; retry when it finishesTwo builds, or a build and a change, on the same pack or moduleWait and retry. The lock is released when the operation ends or fails.
409 on createA pack with that name exists in the groupPick another name.
413 file "x" is N MiB; the maximum upload size is M MiBThe file exceeds max_artifact_size_mbRaise it, and the limits of every proxy in front. See Operations. A proxy answering 413 with its own body (for example nginx's default 1 MiB) is the proxy, not the service.
Upload 400 mentioning content that contradicts the filenameA file named .swu is not a SWUUpload a real .swu, or rename the file.
Artifact upload fails with 500 and version X must be greater than the current latest versionArtifact names are global, and a name can only be reused with a higher versionGive the new file a higher version, or a new artifact name.
Cannot create launch: update pack 'x' has not been built yet (400)The pack is still a draftBuild it first.
Cannot create launch: update pack "x" is per-device encrypted and only N of M devices have a package (400)Some devices have no keyAssign the missing keys and build again. There is no override.
approval_threshold and error_threshold must be between 0 and 100Thresholds are percentagesUse 0-100.
launch X is paused; resume it first (400)The launch was pausedCall resume.
test device X cannot act as this group's canary: device X does not exist (hawkbit mode)The canary check runs before the group's devices exist in hawkBitRun a dry run without test_device_id first (POST .../launch?dry_run=true), which registers the devices as targets.
The device registry or KMS answers 401The service always sends X-Principal-ID: admin-mode, and the gateway in between rejects itPoint dms_endpoint and kms_endpoint at the internal service addresses, or allow that header.

Builds

Symptom or messageLikely causeFix
no sw-descriptor uploaded for update pack "x" vNThe version has no sw-description (each version needs its own)Upload it.
failed to read binaries directory or binaries directory is emptynative mode: nothing was staged, because the build body has no selected_artifact_idsPass the artifact IDs. See the publish guide.
swugenerator failed: exit status NThe tool rejected its input. Its own message is in the service logCheck the sw-description, the file names it references, the algorithm spelling (aes-256-gcm, hyphens required) and the key length.
signing requested but sign_script_path/kms endpoint are not configuredA .swu was asked to be signed without both settingsSet sign_script_path and kms_endpoint.
signing requires key id, algorithm and certificate togetherA partial signature requestSend all three signature_* fields.
failed to sign version manifest: the KMS did not return a PKCS7/CMS signatureThe KMS answered with a bare signatureUse a KMS version that returns CMS. See Signing and encryption.
symKMS SDK client is not configuredsymkms_endpoint is emptySet it. In hawkbit mode also set the symkms block so the routes exist.
failed to fetch key "k" via symKMSWrong key ID or user, or the endpoint points at another instanceThe key belongs to its user_id; symkms_endpoint must be this instance's own address and port.
Per-device build fails mentioning encrypted = trueNo artifact in the sw-description is marked encrypted = true;Mark the artifacts to encrypt.
no devices found for DMS X or none of the N devices ... have a key assigned for firmware-encryptionThe group has no devices in the registry, or none has a keyCheck the group in Lamassu IoT and dms_endpoint; assign firmware-encryption keys.
hawkbit mode: this deployment has no SWU builder configured (501)swugenerator_path is emptySet it, or upload a prebuilt .swu module.
hawkbit mode: this deployment has no SymKMS configured or ... no KMS endpoint configured (501)Encryption or signing asked without symkms_endpoint or kms_endpointSet them.
software module "x" ... is N MB and encrypting it needs about M MB in memorybuild_memory_limit_mb refuses the buildSign without encrypting, split the file, or raise the limit together with the pod's memory.
... is already built; ... release a new version of it to build againA build replaces the module's input filesCreate a new version of the module.

Downloads and presigned URLs

Symptom or messageLikely causeFix
404 SWU not available for device D on pack "x" vNThe pack is per-device encrypted and has no package for that device (its key was missing at build time, or the pack inherited per-device mode from an earlier version), or the build file is gone from the storeAssign the device's key and build a new version. To avoid inheriting, use a separate pack for each encryption variant (see Limitations).
Startup: presign needs its own credentialpresign is enabled without a signing credentialSet presign.access_key_id[_file] and secret_access_key[_file], a read-only pair.
Startup: the presign credential can WRITEThe signing credential has write accessGive it a read-only policy on the objects it serves.
Startup: presign signs with the storage's own credentialSame key as the storageCreate a separate read-only key.
Startup: the store does not accept the presign credentialThe store does not know the key, or the signature does not matchCreate the user in the store; check region and endpoint.
Startup: presign cannot be combined with client-side encryptionencryption.type is not none on that blockUse store-side encryption, or disable presign.
Startup: presign.public_endpoint must be an http(s) originThe value has no scheme, or has a pathUse an origin such as https://updates.example.com.
The device gets 403 from the store after the 302The URL expired before the device started the GET, the signed Host is not what the device used (public_endpoint wrong), the signing key cannot read that prefix, or clocks differRetry (a fresh URL is issued per request); check ttl, public_endpoint and the key's policy.
Downloads stream through the service despite presignA HEAD request, an artifact download by ID in native mode, a store without presign for that block, or the signing failed (logged)Only builds in native mode and the S3 plugin objects in hawkbit mode are redirected.

Updates not reaching devices

SymptomLikely causeFix
Devices cannot download the .swu (native mode)update_domain is not reachable from the device, or is not the full .../updates/v1/ base with a trailing slashUse an address the device can resolve. The Helm chart default lacks /updates.
hawkbit mode: a device gets 401 from DDIhawkBit refuses devices that do not authenticateEnable and use a hawkBit device authenticator. See hawkBit mode.
hawkbit mode: a device gets 429hawkBit's own DoS filter, which limits how often a device may call itSlow the polling and feedback of the device.
hawkbit mode: the launch stays running with no progressThe devices never contacted hawkBit, or they poll a different hawkBitCheck which hawkBit the devices poll, and that the targets exist. A rollout group cannot advance until its devices poll.
hawkbit mode: devices are not found in the groupdms_endpoint is not set, so groups are the group:<id> target tagsSet dms_endpoint, or tag the targets.
A phased launch stays at CREATED (native mode)In the phased workflow some steps are made by WFX or an operatorConfirm them through WFX, or use direct.
A non-swu launch shows SWU states (native mode)It was created with workflow_type: directUse download-install.
The device installs and shows the old versionThe payload version was not changedBump the version before building.
The device ignores new deploymentsSWUpdate keeps the update state of an earlier install as pending test (ustate=1) and refuses a new oneConfirm or reset the device's update state. This is a device setting, not a service one.
The device rejects the .swu and the error mentions decryption or an invalid imageThe .swu is unsigned while the device requires a signature, or the signature is not CMSSign it with a KMS that returns CMS. A signature failure can be reported as an encryption error.
The device fails to decryptThe key used to build differs from the device's key, or the algorithm spelling differsUse the same key and algorithm. Check the assignment in SymKMS.

Scaling and background work

SymptomLikely causeFix
Pods cannot start on different nodesThe ReadWriteOnce volume (both modes while persistence.enabled is true)Set persistence.enabled: false and move artifacts, builds and symkms to S3. See Operations.
Campaign batches never advance (native mode)Leader election is failing, or WFX events are not arrivingCheck the Leases and the RBAC, or set leaderElection.mode: database. The log line leadership acquired appears on the leader.
Scheduled launches never start (native mode)The same background work, which runs on the leaderAs above.
Per-device builds are slowThe CPU limitRaise it. See Resource sizing.
The pod is killed during an upload or an encrypted buildMemory limit, or the temporary disk is fullSize memory for the largest file you encrypt, and give TMPDIR room.

Getting more information

  • Raise app.logs.level to debug, but remember that it prints secrets.
  • GET /updates/v1/capabilities shows the active backend and what it supports.
  • Each replica logs which one leads (leadership acquired, is the leader, standing by).
  • In hawkbit mode, inspect what the service created through hawkBit's Management API (port 8090 in Compose, with the Basic Auth credentials of the configuration). Each hawkBit instance has its own data: query the one named in hawkbit.base_url.
