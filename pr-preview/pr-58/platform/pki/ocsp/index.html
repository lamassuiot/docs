Online validation with OCSP

Query signed status and verify the responder’s response.

Sin cambios en esta página

OCSP queries a certificate’s status and returns a signed response. This guide is for an integrator checking what Lamassu publishes and how the consumer must verify it. For complete identity validation, follow Certificate validation.

How the responder works in Lamassu

The responder retrieves the certificate by serial number and locates its issuing CA in the inventory. It translates persisted status as follows:

Record statusSigned response
ACTIVEGood.
REVOKEDRevoked, with revocation reason and timestamp.
Other states, including INACTIVE and EXPIREDUnknown if the certificate and issuer can be retrieved.

An absent serial number causes a lookup error; it does not guarantee a signed Unknown response. Lookup or signing errors produce an HTTP failure. Treat that as unavailable evidence according to consumer policy.

The issuing CA itself signs the response through its KMS-associated key. A delegated OCSP signing certificate is not used. An imported CA without a usable key cannot sign responses.

The implementation sets thisUpdate approximately one day before response generation and nextUpdate one day after: the declared window is about 48 hours. Inspect received values and apply your freshness policy. The response reflects stored status when queried; a previously cached copy does not change upon revocation.

HTTP endpoints

The service accepts:

MethodVA service pathFormat
POST/ocspDER request, Content-Type: application/ocsp-request.
GET/ocsp/{ocsp_request}DER request encoded using padded URL Base64.

Use POST to avoid client encoding differences. A successful response has Content-Type: application/ocsp-response and a DER body. The public prefix depends on the Gateway; use the URL published in the certificate and checked by the operator.

Check from the interface

OCSP Check shows what Lamassu returns for a selected certificate. Complete the check from the consumer’s network and trust store: a console query does not establish its validation configuration.

To check a change, save an earlier response, revoke a test certificate and request another response. The new query should reflect persisted status; compare timestamps to rule out reuse of an earlier response. If it fails, follow PKI troubleshooting.
