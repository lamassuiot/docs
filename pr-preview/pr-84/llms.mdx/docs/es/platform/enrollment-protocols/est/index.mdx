# Referencia EST (/docs/pr-preview/pr-84/es/platform/iot-fleets/est)



Enrollment over Secure Transport (EST) es un protocolo para obtener y renovar certificados X.509 mediante HTTPS. Un cliente EST se comunica con un servidor EST, que gestiona la solicitud de certificado y facilita los certificados de las autoridades de certificación. El estándar define mensajes, operaciones y mecanismos de autenticación. [RFC 7030](https://www.rfc-editor.org/rfc/rfc7030.html)

Operaciones [#operaciones]

Las rutas de operación se añaden al prefijo `/.well-known/est`, que puede incluir una etiqueta para identificar la CA o el servicio.

| Operación         | Método | Función                                                                 | Soporte del servidor |
| ----------------- | ------ | ----------------------------------------------------------------------- | -------------------- |
| `/cacerts`        | GET    | Obtener certificados de CA.                                             | Obligatorio          |
| `/simpleenroll`   | POST   | Solicitar un certificado inicial mediante una CSR.                      | Obligatorio          |
| `/simplereenroll` | POST   | Solicitar la renovación o sustitución de clave de un certificado.       | Obligatorio          |
| `/serverkeygen`   | POST   | Solicitar una clave generada por el servidor y el certificado asociado. | Opcional             |
| `/csrattrs`       | GET    | Consultar atributos sugeridos para la CSR.                              | Opcional             |
| `/fullcmc`        | POST   | Enviar una solicitud Full CMC.                                          | Opcional             |

Autenticación y mensajes [#autenticación-y-mensajes]

EST utiliza TLS para proteger el intercambio. El cliente autentica al servidor y el servidor autentica y autoriza al cliente mediante los mecanismos definidos por el estándar. La distribución inicial de certificados de CA tiene condiciones particulares para establecer la confianza. [RFC 7030, secciones 3.3 y 4.1](https://www.rfc-editor.org/rfc/rfc7030.html)

Las solicitudes de `/simpleenroll` y `/simplereenroll` utilizan una CSR PKCS#10. La respuesta de certificado utiliza PKCS#7. La respuesta de `/serverkeygen` es `multipart/mixed` y contiene la clave y el certificado. El estándar también define la solicitud y la respuesta Full CMC y el formato de atributos de CSR. [RFC 7030, sección 3.2.4](https://www.rfc-editor.org/rfc/rfc7030.html#section-3.2.4)
